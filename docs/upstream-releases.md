# 上游版本更新记录（v0.3.0 → v0.5.3）

上游仓库是 <https://github.com/bashalarmistalt/decimen-optical-transfer>，最新版本为
**v0.5.3（2026-08-20）**；截至本文整理时 `main` 上没有 v0.5.3 之后的新提交。

**本目录当前交付的核心就是 v0.5.3**（取自上游 Release 的独立构建产物，SHA-256 已核对）；
**v0.3.0** 则是从 [yunso.net 小云快传](https://www.yunso.net/share) 页面里逐字节还原的版本，
两份原始文件都留在 `vendor/`，用 `node tools/build-cores.mjs --version=` 可随时切换。

一句话概括这段时间的更新：**两次线格式破坏性变更（v2、v3）、许可改为 AGPL、解码器独立成项目、
性能提升到数百 KB/s、支持多码同屏、12 种语言、可导出成视频动画。**

---

## 线格式与兼容性

| wire | byte 0 / byte 1 | 帧头 | 版本 | 关键变化 |
| --- | --- | --- | --- | --- |
| **v1** | `0xD1 0x0C` | 20 B | 0.1.0 – **0.3.0（本目录）** | 无版本字段；鲁棒孤子（robust soliton）喷泉码 |
| v2 | `0xD1 0x0D` | 20 B | 0.4.0 | 系统性轮播喷泉码；仍然没有版本字段 |
| v3 | `0xD1 0xC3` | 22 B | 0.5.0 – 0.5.3 | 第 2 字节版本号、第 3 字节 flags |

- **0.5.x 之间互通**（0.5.0/0.5.1/0.5.2/0.5.3 线格式未变）；
- **0.4.x 与任何其它版本都不通**（两个方向都不行）；
- **本目录的 v0.3.0 与 0.4.x / 0.5.x 都不通**，但发送端与接收端自成本对，彼此可用；
- 失败时的表现（上游设计的一个重点）：
  - 0.5.x 接收端遇到 v1/v2 发送端 → 明确提示「那台设备在发旧的 Decimen 格式，请更新发送设备」；
  - 0.5.x 发送端遇到 0.5.0 之前的接收端 → 老接收端只会停在「无信号」，因为它连版本字段都没有；
  - 非 Decimen 的二维码、以及自相矛盾的坏帧 → **保持沉默**（摄像头会看到街上的各种二维码，不能乱提示）。

## v0.4.0（2026-08-09）

**许可**
- 改为 **AGPL-3.0-or-later**；v0.3.0 及更早版本仍按 MIT 提供。`NOTICE` 记录第三方与 MIT 时期的署名。
- 所有构建产物的 banner 都带上 SPDX 标识与对应源码链接；如需闭源商用可另行购买商业许可。
- PR 从「一律关闭」改为「需签 CLA，选择性接受」。

**协议：wire v2**
- **喷泉码重做**为「系统性轮播」：先按顺序把 K 个块各发一遍，再发 K 个中等度数（4–24）的确定性修复帧，然后循环。
  零丢包时所需帧数正好是 **1.00 倍**（v1 的孤子分布是 1.15–1.6 倍）；在 5%–50% 丢帧下实测恢复速度比 v1 快 1.7–1.8 倍。
- magic 第二字节 `0x0C → 0x0D`，让新旧两端干净地互相拒绝，而不是静默错位。

**解码器与速度**
- 解码器独立成项目 **[decimen-codec](https://github.com/bashalarmistalt/decimen-codec)**：QR-only、reader-only 的 zxing-cpp WASM 构建，
  带 `readTracked`（用上一帧的位置四边形重建像素映射，跳过检测），单次解码快 2–4 倍、体积约为原版 1/4。
- **多发码发送端**：每帧 1/2/4/6 个二维码，竖屏优先「先高后宽」排布；每个码是一路独立喷泉帧，4 码即 4 倍帧率。
- **按码裁剪跟踪的接收端**：记住每个码上次的位置，下一帧只在带内边距的裁剪区里解码，可并行到多个 worker；丢锁后激进重扫全帧。
- 默认发送帧率提升到 **60 fps**；标签页被切到后台导致卡住时会明确警告。
- 接收端新增**锁定指示**画布叠加层、以及「所见即所解」的 `contain` 取景框；解码 worker 默认拉到设备上限（按 `hardwareConcurrency` 收敛）。

**其它**
- 公布基准：桌面→手机 4 码 **418.5 KB/s 持续 / 601.5 KB/s 峰值**，手机→手机 2 码 **199.2 / 340.8 KB/s**，每个数字都可点进完整的诊断报告。
- `npm run diagnostics` 结构化运行报告，正式构建里会被编译剔除。

## v0.5.0（2026-08-12）

**协议：wire v3（破坏性）**
- 帧头 20 → **22 字节**，终于带上版本：固定双魔数 `0xD1 0xC3` + 版本字节 + flags 字节。
- 接收端必须能分辨并「说出来」：`older-sender`（提示更新发送端）、`newer-sender`（提示更新本应用）、
  `unsupported-flags`（同上）、`foreign` / `malformed`（保持沉默）。用两个魔数字节把误报率从 0.402% 降到 0.006%。
- flags 字节预先切成两半：`0x0F` 必须理解（未知位 = 硬拒绝）、`0xF0` 可安全忽略（直接透传）；
  `FLAG_ENCRYPTED`（`0x01`）已预留，将来加密只需一个 bit 而不必再来一次格式破坏。
- 补充**线格式契约文档** `versioning.md` 与 **golden vectors**，以及一个跨层测试：
  300 KB 不可压缩数据经容器 + 喷泉码 + 成帧往返，注入约 15% 帧丢失，要求完全恢复、哈希一致、开销 < 1.3×。

**隐私**
- 新增 **「自动展示收到的文件」** 开关（默认开）：关掉后，图片/视频/音频/文本要先点 Show 才显示，
  且未 Show 的文件不会写入媒体缓存。
- 「清除 Decimen 缓存」只在真有缓存时出现。

**其它**
- 解码器升级 decimen-codec 0.2.0（多为面向原生的 C ABI 工作，WASM 路径不变）。
- 站点补 favicon / robots / sitemap / canonical，OG 卡片的速度数字改为从基准记录生成。

## v0.5.1（2026-08-12）

- 接收设置里新增 **摄像头选择器**：自动选择在某些手机上不可靠（如 P30 Pro 会把长焦当成后置主摄，或直接给前置）。
- 摄像头列表在授权后才显示真实设备名；**传输中也能实时切换**（停旧轨→开新机，解码状态不丢，帧在切换期间暂停）；
  新摄像头启动失败会退回原来那台；能力灰显（fps / 宽度上限）按镜头重置。

## v0.5.2（2026-08-12）

- **12 种语言**：英、西、葡（巴西）、法、德、意、俄、印地、**简体中文**、日、韩、阿拉伯（含完整 RTL 布局）。
- 每种语言是独立的页面树（`/es/send/`、`/ar/receive/`…），带本地化标题、社交卡片、hreflang；
  语言切换器只做导航、绝不按浏览器语言重定向；离线 PWA 会预缓存全部语言树；独立 HTML 版内嵌全部语言目录并在打开时按读者语言选择。
- 非英语文案都是机器起草，会在页脚用该语言注明「未经人工审校」，欢迎以 PR 提交校对。
- 协议错误改为错误码、显示时再本地化；构建下限提升到 **ES2022**（Chrome/Edge 89+、Firefox 89+、Safari 15+）。

## v0.5.3（2026-08-20，最新）

- **导出动画**：传输设置底部新增 `Export animation`，把同样的线格式帧渲染成文件 ——
  任何摄像头对着**播放中的文件**（浏览器标签页、嵌入页面、视频）都能像看实时发送端一样接收。
  - 两种格式：循环 **APNG**（一个文件，所有浏览器都能播）或 **PNG 序列 ZIP**（给视频编辑器，附 `frames-per-second.txt`）。
  - 四个参数：格式、帧率（默认 10 fps，取 30/60 的整除值避免重编码丢帧）、模块缩放（默认 4×，1px 模块扛不住视频压缩）、循环次数（默认 2）。
  - 参数下方会先预估帧数/体积/循环时长，再变成渲染进度；体积是「实测」而不是模型估算。
  - 实时流与导出共用同一条 QR 渲染路径，因此不会各自漂移；新增的 bilevel PNG / APNG / store-mode ZIP 写入器不引入新依赖。
- 界面：面板标题层级修正；流状态行把文件名与句子其余部分区分开（且不假设各语言的语序）。
- 导出相关的控件与提示已翻译进全部 12 种语言。

## 版本状态与本目录的关系

| 版本 | 线格式 | 许可 | 在本目录里 |
| --- | --- | --- | --- |
| **v0.5.3** | v3 | AGPL-3.0-or-later | **当前交付**（`send.html` / `receive.html` 由它生成） |
| v0.3.0 | v1 | MIT | 保留在 `vendor/`，`--version=0.3.0` 可切回 |

```bash
node tools/build-cores.mjs                     # v0.5.3（默认）
node tools/build-cores.mjs --version=0.3.0     # 站点内嵌的 MIT 版
node tools/build-cores.mjs --locale=zh-Hans    # 把界面固定在简体中文
```

⚠️ 两个版本线格式不同，**发送端与接收端必须同版本**：0.5.x 之间互通；
v0.3.0 与 v0.4.x / v0.5.x 双向都不通；v0.5.x 接收端遇到 v1/v2 发送端会明确提示「更新发送设备」，
而 v0.3.0 接收端遇到新版发送端只会停在「无信号」。

想跟进更新：从 [Releases](https://github.com/bashalarmistalt/decimen-optical-transfer/releases) 下载
`decimen-vX.Y.Z-sender.html` / `-receiver.html`（自包含单文件），放进 `vendor/`，
在 `tools/patch-core.mjs` 的 `VERSIONS` 里加一条记录，然后 `node tools/build-cores.mjs --version=X.Y.Z`。
v0.5.2 起上游自带多语言，本地化不需要再额外做（v0.3.0 才需要 `js/optical-i18n.js` 那一层）。
